# AGENTS.md — Development & Agent Guidelines

## 1. Project Overview

`mumble-server-rest-api` is a RESTful API wrapper built with **FastAPI** to manage and administer virtual Mumble servers (**Murmur**) via ZeroC Ice RPC. It is a modern FastAPI reimplementation/successor to the legacy Flask-based `Murmur-REST`.

### Core Technology Stack
- **Framework**: FastAPI (v0.111+), Starlette, Uvicorn
- **Data Validation & Schemas**: Pydantic v2
- **RPC & Integration**: ZeroC Ice 3.7 (`python3-zeroc-ice` / `Ice` Python extension)
- **IDL & Stubs**: Murmur Slice definitions (`Murmur.ice`, `Murmur_ice.py`)
- **Containerization**: Docker (Debian 12 Bookworm base) & Docker Compose

## 3. Environment & Configuration

Configuration is loaded from environment variables in `settings.py`:

| Variable | Default | Purpose |
| :--- | :--- | :--- |
| `MURMUR_ICE_HOST` | `localhost` | Hostname or IP of the Murmur server running Ice |
| `MURMUR_ICE_PORT` | `6502` | Port for the Murmur Ice interface |
| `ICE_SECRET` | `""` (empty) | Murmur Ice administrative secret (if configured in `murmur.ini`) |
| `ICE_MESSAGE_SIZE` | `1024` | Maximum Ice message size (KB) |

Connection string constructed: `Meta:tcp -h <HOST> -p <PORT> -t 1000` (1000ms timeout).

## 4. Development Workflow & Running the App

### Why Docker is Required
ZeroC Ice 3.7 requires compiled C++ extensions (`zeroc-ice`). Native pip wheels are unavailable for many modern platforms (especially Windows and newer Python versions like 3.12+). The primary execution environment is Debian Bookworm with the official ZeroC Ice repository.

### Running with Docker Compose
```bash
docker compose build
docker compose up -d
```

### Accessing API Documentation
When running:
- **Interactive Swagger Docs**: `http://localhost:2332/docs`
- **ReDoc Documentation**: `http://localhost:2332/redoc`
- **Version Endpoint**: `http://localhost:2332/`

## 5. Architectural Conventions & Guidelines for AI Agents

When editing or extending this codebase, adhere strictly to these conventions:

### 5.1 Asynchronous vs Synchronous Ice RPC Calls
- **CRITICAL**: ZeroC Ice Python bindings make **synchronous, blocking network I/O calls** over TCP sockets.
- **Rule**: Do **NOT** call Ice RPC methods directly inside an `async def` route without offloading to a threadpool. Doing so blocks FastAPI's event loop and starves all concurrent requests.
- **Preferred Pattern**:
  - Use standard `def` for route functions that do synchronous Ice RPC. FastAPI will automatically dispatch them to an asynchronous worker threadpool (`starlette.concurrency.run_in_threadpool`).
  - Or explicitly wrap calls with `run_in_threadpool` if the route requires `async def`.

### 5.2 Ice Lifecycle & Connection Management
- Avoid doing top-level network I/O or `Murmur.MetaPrx.checkedCast(_proxy)` at import time in `app/__init__.py`. Import-time network calls cause the application to crash immediately if Murmur is booting up, and break linters/test imports.
- Use FastAPI's `lifespan` handler (`@asynccontextmanager async def lifespan(app: FastAPI)`) or a lazy dependency injection provider (`Depends(get_ice_meta)`) to manage the communicator and meta proxy.

### 5.3 Error Handling & Ice Exceptions
- Murmur Ice calls can raise:
  - `Ice.ConnectionRefusedException`, `Ice.SocketException`, `Ice.TimeoutException` -> Map to `503 Service Unavailable` or `504 Gateway Timeout`.
  - `Murmur.InvalidSecretException` -> Map to `401 Unauthorized` or `500 Misconfigured Server Secret`.
  - `Murmur.ServerBootFailedException` -> Map to `400 Bad Request` or `500 Server Boot Failed`.
- Do not let unhandled `Ice.Exception` bubble up as raw 500 internal server errors without informative messages.

### 5.4 API Route Design & RESTful Standards
Legacy routes in `app/server_router.py` mix RPC-style GET/DELETE endpoints with query parameters (`/getAllServers`, `/getServerDetail?id=1`, `/deleteServer?id=1`).
When modifying or adding routes, follow RESTful conventions:
- Use plural resource nouns: `/servers`, `/servers/{id}`
- Use proper HTTP methods:
  - `GET /servers` — list all servers
  - `POST /servers` — create a new server
  - `GET /servers/{id}` — get single server detail
  - `DELETE /servers/{id}` — delete server
  - `POST /servers/{id}/start` — start server
  - `POST /servers/{id}/stop` — stop server
  - `GET /servers/{id}/logs` — get server logs
- Maintain backward compatibility where needed, or provide clean aliases.

### 5.5 Security & Data Sanitization
- Never return server passwords or administrative Ice secrets in plaintext API responses.
- Implement authentication (API Key, Bearer Token, or HTTP Digest) for administrative endpoints that start, stop, or delete servers.

### 5.6 Data Serialization (`obj_to_dict`)
- ZeroC Ice objects often lack standard Python dict conversions or use custom attributes/slots.
- In `app/utils.py`, ensure `obj_to_dict` safely handles `None`, primitive scalars (`int`, `float`, `str`, `bool`), lists, and nested mappings without triggering `AttributeError: 'NoneType' object has no attribute '__dict__'`.

## 6. Known Quirks & Bugs to Address

1. **Duplicate Function Name**: In `app/server_router.py`, the `POST /{id}/stop` endpoint was declared as `def start(id: int):`, colliding with the `POST /{id}/start` handler. Rename it to `def stop(id: int):`.
2. **Import-Time Blocking**: `app/__init__.py` connects to Ice on module import. If Ice is down, the entire app fails to boot or test.
3. **Unused Imports**: `main.py` imports `HTTPDigest` without using it.
4. **Dockerfile apt-key Deprecation**: Dockerfile uses `apt-key adv` which is deprecated in Debian 12 Bookworm; replace with `/etc/apt/keyrings` keyring management.
5. **Compose Environment Placeholder**: `compose.yaml` has placeholder `MURMUR_ICE_HOST= your mumble server address` and a commented-out Mumble server container.
